# AllSafe AI Trading — Security Audit Revalidation Report (`SECURITY_AUDIT_REVALIDATION_REPORT.md`)

- **Audit Date**: November 5, 2026
- **Verification Branch**: `audit/landing-auth-integration-verification`

## 1. Revalidation of Authentication & IP Security Controls

| Control Requirement | Code Location | Verification Findings & Remediation | Verdict |
| :--- | :--- | :--- | :--- |
| **Admin Login Exempt from IP Restrictions** | `apps/api/app/auth/security.py` (`is_client_ip_allowed`, lines 351–384) | Super Admin (`is_super_admin=True`) and administrators (`role in {'admin', 'super_admin'}` with `global_admin_ip_access=True`) return `True` prior to any `allowed_ip_spec` evaluation, even if a legacy static IP was stored on the admin record. | **PASS** |
| **Customer IP Restrictions Enforced** | `apps/api/app/auth/security.py` & `store.py` (`authenticate`, `verify_request_session`) | Customer accounts (`role='user'`) are evaluated against `allowed_ip` on login, session verification (`/api/v1/auth/me`), and token refresh (`/api/v1/auth/refresh`). Unauthorized IPs receive `403 Forbidden` and trigger `auth.login.ip_restricted` audit logs. | **PASS** |
| **Privilege Escalation Prevention (Role / JWT / Profile)** | `apps/api/app/auth/security.py` (`verify_jwt_with_jwks_or_secret`) & `store.py` | 1) `LoginRequest` and self-service endpoints do not accept `role` or `is_super_admin`. 2) `verify_jwt_with_jwks_or_secret()` strips `role`, `is_super_admin`, and `allowed_ip` from client-writable `user_metadata`. 3) `verify_request_session()` always loads `user = self._users.get(user_id)` from the server store and enforces `user.role` and `user.allowed_ip` from the server record—never from token claims. | **PASS** |
| **IP Header Anti-Spoofing & Proxy Trust** | `apps/api/app/auth/security.py` (`extract_client_ip`, `_extract_valid_xff_hops`, `is_trusted_proxy_peer`) | **Remediated during revalidation**: Previously, `extract_client_ip()` took `split(",")[0]` from the first `X-Forwarded-For` header. Now, it checks `trust_proxy_headers` and `is_trusted_proxy_peer()`, collects all valid IPs across duplicate `X-Forwarded-For` headers, discards malformed tokens, and walks **right-to-left** skipping up to `trusted_proxy_hops` internal proxies so prepended client headers cannot spoof an allowed IP. | **PASS (REMEDIATED)** |
| **Missing, Malformed, Duplicate, IPv4, IPv6, IPv4-Mapped IPv6** | `apps/api/app/auth/security.py` (`normalize_ip_string`) | **Remediated during revalidation**: Added `strict=True` mode returning `""` for malformed strings (`not-an-ip`, `999.999.999.999`, unclosed brackets, non-numeric ports, SQL injection strings). Canonicalizes `::ffff:203.0.113.44` and `[::ffff:203.0.113.44]:443` to `203.0.113.44` and strips `%zone` suffixes. | **PASS (REMEDIATED)** |
| **Rate Limiting & Concurrency** | `apps/api/app/auth/store.py` (`_check_ip_rate_limit`, `self._lock = threading.RLock()`) | Per-IP sliding window (`12 req/min` default) and per-account failed-attempt lockout (`5` failures -> `900s` lockout) are guarded by a re-entrant thread lock (`threading.RLock()`). Verified with 18 concurrent threads in `test_concurrent_rate_limiting_session_refresh_and_password_rotation_revocation`. Multi-worker limitation (in-memory per-process state when Redis is not attached) is explicitly documented in `KNOWN_LIMITATIONS_AND_RESIDUAL_RISKS.md`. | **PASS** |
| **JWKS Caching, Refresh Throttling, Unknown `kid`, Expired & Invalid Signatures** | `apps/api/app/auth/security.py` (`JWKSCache`, `verify_jwt_with_jwks_or_secret`) | **Remediated during revalidation**: Added `JWKSCache` with `3600s` TTL and `30s` refresh cooldown on unknown `kid`. Verifies `RS256` (RSA-2048), `ES256` (P-256), and `HS256` signatures; rejects `alg="none"`, expired (`now >= exp`), premature (`now < nbf`), and tampered signatures. | **PASS (REMEDIATED)** |
| **Password Change, Logout, Session Expiry & Refresh** | `apps/api/app/auth/store.py` & `routers/auth.py` | **Remediated during revalidation**: Added `POST /api/v1/auth/refresh` (revoking old `jti` and issuing a new token/CSRF pair) and updated `change_password()` to revoke existing sessions upon password hash rotation. | **PASS (REMEDIATED)** |
| **Supabase RLS Policies & Service-Role Usage** | `supabase/migrations/*.sql` | All 12 public tables enforce `ENABLE ROW LEVEL SECURITY` and `FORCE ROW LEVEL SECURITY`, revoke `anon`/`PUBLIC` privileges, and use `(SELECT coalesce(current_setting('request.jwt.claims', true)...))` `InitPlan` expressions. `trg_protect_super_admin` prevents Super Admin deletion, demotion, or IP lockout at the PostgreSQL layer. | **PASS** |
| **Zero Secret Exposure in Logs or Frontend Bundles** | `apps/api/app/config.py`, `groww_auth.py`, `apps/web/src/lib/clientApi.ts` | `Settings.__repr__` redacts all secrets (`[REDACTED]`), `redact_groww_secrets()` scrubs audit/error logs, and `clientApi.ts` references only `process.env.NEXT_PUBLIC_API_BASE_URL`. | **PASS** |
